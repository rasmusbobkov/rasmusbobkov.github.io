# Tähelugu

An Estonian-first astrology app for the general public: a daily coach that
speaks from a real natal chart, not a chart viewer. The daily story is the
landing surface; the chart wheel is the depth layer underneath it.

- The natal chart is computed **on the device**, from birth date, time and
  place. Birth data never leaves the browser; there is no backend.
- The interface is **Estonian first**; the ET/EN switch is present and English
  is marked as coming.
- The Estonian vocabulary follows the concept board: *sünnikaart*, *tõusumärk*,
  *maja*, *ruut*, *vastasseis*, *trigoon*; technical loanwords live in the
  glossary.

Architecture, the invariants tied to tests and the decision log live in
[`docs/`](docs/README.md); the build history stays in `RECORD.md`.

## Run

```
npm install            # use --legacy-peer-deps if npm's resolver balks on vitest peers
npm run dev            # astro dev --background; stop/status/logs via npm run dev:<cmd>
npm test               # docs shape and file-length checks, then the correctness, privacy, story-content and spelling gates
npm run docs:check     # documentation shape check only; npm test runs it first through pretest
npm run build          # static output into dist/
```

`pretest` also runs `scripts/check-file-lengths.sh`, which fails on any code
file longer than 1500 lines: split the file rather than raise the cap.

## Stack

- **Astro**, static output only. No server runtime, no API routes, no SSR.
- **Swiss Ephemeris compiled to WebAssembly** (`@swisseph/browser`), running on
  the built-in **Moshier** ephemeris — no ephemeris files are fetched, ever.
  The ephemeris payload is ≈ 0.2 MB gzipped, far under the 2.5 MB budget; the
  trade-offs behind that choice are recorded in
  [`docs/decisions/0002-swiss-ephemeris-wasm-and-agpl.md`](docs/decisions/0002-swiss-ephemeris-wasm-and-agpl.md)
  and asserted by tests.
- **Luxon** (timezone offsets from the IANA tz data built into the browser) for
  historical timezone resolution — correct across Estonia's Moscow-time era.
- Fonts are self-hosted; no third-party requests of any kind.

## Correctness gate

`tests/chart-fixtures.test.ts` asserts five documented charts (1961–1990,
latitudes 64N…−36.8S, including an Estonian 1961 birth under the historical
Moscow-time offset +03:00) against references produced with the official
Swiss Ephemeris C library 2.10.03:

- planetary longitudes and the mean lunar node within **0.01°**,
- Placidus house cusps, Asc and MC within **0.05°**,
- each fixture's Sun additionally pinned against **NASA JPL Horizons**
  (agreement ≤ 0.00002°).

The transit engine of the daily story reads the same five instants from the
transit side at the same 0.01° longitude tolerance (`tests/transits.test.ts`).

Fixtures: `tests/fixtures/natal-charts.json`, generated by
`scripts/generate-fixtures.mjs` (manual, engine-change only). No expected
value was derived from any consumer astrology app.

## Privacy, mechanically enforced

`tests/privacy.test.ts` fails if `src/` calls `fetch`, `XMLHttpRequest`,
WebSockets, `sendBeacon` or `postMessage`, and re-scans the built output. The
one exception is the approved measurement: `src/lib/events.ts` sends one GET
per wired event — a visit, birth data given, a story opened — to a cookieless
counter, carrying the event name and the app version and nothing else. The
only remote addresses the source names are that counter and the two credits
the footer displays — the project's own source and GeoNames — and nothing
loads from the credits: a link a visitor may follow is not a request the page
makes. The public metrics page at `/mõõdikud/` reads its numbers from the
build-time snapshot, so it sends no request of its own. Persistence is a
versioned localStorage schema with JSON export/import; the share link encodes
only the derived Sun/Moon/Rising sign placements in the URL fragment — never
birth time or place.
