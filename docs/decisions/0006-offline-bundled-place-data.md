# 0006 — Bundle place and timezone data instead of geocoding

## Context

Birth place has to resolve to coordinates and an IANA timezone, including historical offsets: Estonia used Moscow time (+03:00) before 1989, and DST only began in 1981. A geocoding API would both add a network call carrying birth data and introduce a service dependency.

## Decision

Ship two committed JSON datasets under `src/data/`: Estonian settlements and districts (all `Europe/Tallinn`) and the top 3 000 world cities with their IANA timezone. Search is local. Historical offsets come from Luxon and the IANA tz data built into the runtime. The world set is code-split and loads lazily on first use.

## Consequence

Place search works offline and cannot leak a birth place. The datasets are bounded: an arbitrary village or a private address is not in the list, so the user picks the nearest listed place, and world coverage above the population cut-off. The data is a committed artifact generated by a manual script, so refreshing it is a deliberate change rather than a runtime fetch.
