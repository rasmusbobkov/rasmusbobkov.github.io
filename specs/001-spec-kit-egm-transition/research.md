# Research: workflow transition

Spec Kit 1.2.5 provides native constitution, specification, plan, task and preset facilities. The independently maintained EGM port 0.9.1 at release commit `31a141167f732aa79d9bd74a88743aaac7b079ce` provides seven design/document commands. Its archive SHA-256 is `920f2570be2d40f2a5abe359dd7f58658e90aea317b38438bb8444f8a01d4deb`.

The prior local preset 0.1.1 replaced the upstream no-recommendation rule and repaired review-report overwriting and cross-feature issue-ID collisions. Removing it entirely would restore those defects. Version 0.2.0 retains the fixes while mapping EGM drafting to the canonical feature plan and adding the adapted plan template. The old custom manual is removed rather than renamed or duplicated. Product rules, decisions and history retain their existing owners.

Host project sessions can receive project skills and the first mate can coordinate fresh reviewers. Previous bounded evidence established a documentation skill journey and coordinated source-bounded review, not automatic EGM delegation, persona registration, nested orchestration or a complete automated loop. This transition requires new-version evidence; older runs are historical.

Alternatives: preserving the old manual as a parallel authority was rejected because the selected direction replaces it. Installing both EGM distributions or a second runner was rejected because neither is required for the project-local port. A backlog migration was rejected; existing product and technical trackers retain their roles, with one canonical issue per outcome.
