## Summary

Replace the current single relevant EGM phase for small understood corrections with zero EGM phases. Keep all five design phases for significant changes, and keep one independent native delivery-review track for either route. This changes development documentation only, not the application or installed tooling.

A **small understood correction** means a bounded correction to accepted intent whose cause, scope and expected result are understood and which has none of the significant triggers below. This plan uses “small understood correction” for that single category.

The first mate classifies impact from current accepted intent, not line count. New behavior, shared contracts, saved-data/security boundaries, workflow changes, unresolved architecture or ambiguity select the significant route. Missing or stale intent stops affected work for reconciliation. Small corrections reuse valid intent and artifacts rather than generating a new design ceremony.

## Alternatives and trade-offs

| Alternative | Benefit | Cost or retained risk | Disposition |
| --- | --- | --- | --- |
| Keep one focused EGM phase for each small understood correction | Earlier independent design perspective even on bounded repairs | Adds a separate design handoff when accepted intent and cause are already understood; does not replace implementation/proof review | Not selected; retain design scrutiny when a significant trigger or uncertainty exists instead |
| Zero EGM phases for small understood corrections, five for significant work, one native delivery track for both | Keeps design and delivery responsibilities distinct without a routine extra design handoff for understood repairs | Classification can be wrong; current intent, recorded reasons, ambiguity-to-significant and independent change/scenario review mitigate but do not eliminate that risk | Selected accepted scope |
| Five design phases for every correction | Uniform design-stage coverage | Repeats design assessment of unchanged accepted decisions and adds required reviewer handoffs regardless of impact | Not selected; disproportionate for understood corrections, while significant changes retain all five |
| Add overlapping EGM-Lite or external diff-review pipeline | Another implementation-review perspective | Duplicates the native committed-change/proof track and introduces extra orchestration; design review still cannot prove execution | Not selected; reuse the existing native track and installed port |

These are qualitative coordination and responsibility trade-offs, not measured token, cost or latency savings. None of the options removes the full project gate or separate merge authority. Missing intent does not justify choosing the cheaper route; affected work stops pending reconciliation.

## Review responsibilities

**Spec Kit** is the installed specification-driven development toolkit: its project-local procedures turn accepted intent into requirements, a technical plan and derived execution tasks. **EGM** means Elephant-Goldfish Model: an author maintains the design while fresh independent reviewers examine it through the five perspectives below. The installed procedures are `.agents/skills/speckit-specify/SKILL.md`, `speckit-plan/SKILL.md`, `speckit-tasks/SKILL.md`, `speckit-analyze/SKILL.md` and `speckit-egm-review/SKILL.md` under that same skills directory. They are agent instructions, not additional standalone review executables. Read the applicable installed procedures for the assigned operation; standalone comprehension retains its separate plan-only design-input boundary.

Spec Kit owns requirements, the technical plan and derived execution tasks. EGM judges design. The native delivery-review track judges the committed implementation/documentation and scenarios, then separately judges author evidence. None substitutes for the others, and one track does not mean one model call.

Significant work uses fresh reviewers in order: initial zoom out, standalone comprehension, design critique, intermediate zoom out, implementation readiness. The first mate launches direct native host tasks only after the author supplies real pinned inputs. Initial zoom out receives this actual draft and declared baseline context. Comprehension receives this plan alone as design input, without the author conversation, explanatory sources, earlier reports or automatic linked-file expansion. Other phases receive declared appropriate current context and prior findings where required.

Each phase has a distinct question and output:

1. **Initial zoom out**: the skeptical architect tests whether the overall approach solves the root problem simply and reuses existing infrastructure; the inventive catalyst looks for false compromises and simpler alternatives. Aggregate both attributed reports before progression.
2. **Standalone comprehension**: a fresh reader paraphrases the proposal and existing system from the plan alone, then identifies missing explanations. Preserve the complete paraphrase, not just deficiency counts.
3. **Design critique**: design, structural and style reviewers test the high-level design's requirements, boundaries, organization and clarity. Aggregate findings, resolve them in the canonical plan and retain the distinct critique report.
4. **Intermediate zoom out**: the skeptical architect rereads the full current plan with previous findings and dispositions to check that repairs still form a coherent, simple solution rather than accumulating workarounds.
5. **Implementation readiness**: readiness, codebase-details and style reviewers check the detailed implementation section for executable steps, dependencies, compatibility with existing project sources and verifiable acceptance. This is design judgment before implementation, not code-review clearance.

For each phase the author reads actual reports, preserves required reviewer identities/status and dispositions, and requests the next phase only after the phase's completion rules are met. A proposed repair is not a clean review. A missing reviewer or unresolved blocking finding stops progression; explicit gap reporting is required. Critique and readiness additionally follow the loop convergence rules below.

Before readiness, update the derived tasks to match the final specification and plan. One assigned readiness reviewer applies Spec Kit analyze to that exact trilogy in the same report; separate design findings from consistency/coverage findings. Other reviewers do not duplicate that analysis. Additional requirements checklists need a concrete domain gap, not a stage name. Preserve phase-specific reports, attributed findings and existing loop limits. Missing reviewers or unresolved blockers are not clearance.

### Finding cycles, limits and affected repeats

For this workflow, an unresolved Blocker or Major blocks the relevant phase or delivery judgment; Nits alone do not block. This applies to direct comprehension and both independent delivery judgments as well as critique/readiness. Severity is not silently downgraded. Clearance requires every required reviewer to have completed and every Blocker/Major to be either independently verified as repaired or validly disposed of under the authority rules below. Passing tests or an author's repair statement cannot close an independent finding.

The author proposes resolver dispositions but cannot unilaterally settle a disputed Blocker/Major. A contest must cite a concrete claim and counter-evidence available within the reviewer's permitted inputs; a comprehension gap cannot be contested merely because another unread document explains it. The assigned independent reviewer checks whether that evidence defeats the finding and records agreement or continuing disagreement. The first mate coordinates reconciliation and records its authority; disagreement stays open until resolved, not automatically settled by the author's label. If the ordinary review allowance is exhausted, that verification itself requires a specifically authorized continuation; renaming it disposition checking does not avoid the limit.

Accepted risk is not an author's or reviewer's waiver of accepted requirements, project stop rules or captain-owned decisions. The author reports the exact residual impact and requests a captain decision only when resolving it would materially change approved scope or require an exception the captain can grant. The first mate records that actual decision and reconciles the affected specification and authority before further work. No risk acceptance may claim an unresolved required safety boundary was satisfied, turn a failed review into a clean result, or bypass a higher-authority prohibition. A risk that needs no scope exception still needs explicit attributed disposition and independent confirmation that no required acceptance condition remains violated; otherwise its Major/Blocker remains open. No accepted-risk or contested disposition is being used to clear this feature's current comprehension findings.

The installed review-stage wrapper permits at most one re-audit of a stage after repairs. Comprehension therefore gets its initial review and one recheck of the revised plan; unresolved blocking gaps after that stop for first-mate reconciliation rather than another automatic cycle. The critique/readiness antagonistic subloop separately allows up to five rounds and requires two consecutive clean rounds to converge. A clean round has no unsettled Blocker or Major and all required reviewers completed; Nits alone do not block. Determine cleanliness before applying that round's repairs. An applied fix is not a settled finding: recurrence means the fix failed or was reintroduced. Preserve justified contests/explicit accepted-risk dispositions so an unchanged settled finding is not reopened merely by a new reviewer.

Count two nested units, not one shared retry budget. For critique/readiness, **one outer stage audit invokes the complete inner review loop** and receives its final report only when that invocation returns. Each inner round runs the required reviewer set on current pinned inputs, aggregates findings and records dispositions. Continuing that same invocation to another permitted round is not an outer stage re-audit. Preserve the installed confirmation checkpoint after resolution before another inner round; the author does not infer permission from available numerical budget.

Examples inside one critique/readiness invocation:

- Round 1 fails, round 2 is clean, round 3 is clean: convergence at round 3 within the initial outer audit, not three outer audits. The first failed round is not made clean retroactively by applying its repairs.
- Fail, clean, fail, clean, clean: convergence at round 5. The middle failure resets the consecutive-clean count.
- The fifth round is only the first consecutive clean result: no convergence; stop at the inner cap. A sixth round requires explicit continuation, even though the fifth result itself has no blocking finding.
- Churn (a new finding caused by a fix that would disappear on reverting it) stops the inner invocation before the numeric cap. Preserve open findings and ask through the host rather than silently continuing.

Only after the complete invocation returns does the outer stage report/checkpoint decide progression or a stage re-audit after further stage-level repair. That re-audit starts a new complete subloop invocation with its own five-round/two-clean accounting, and uses the wrapper's single permitted outer re-audit. Inner round 3 in the first example does not consume that outer allowance. A new invocation cannot be used merely to conceal an unapproved cap/churn continuation. Record invocation identities, inner round counts and the outer re-audit count separately.

Comprehension has **no inner antagonistic subloop**: one direct plan-only assessment is the initial stage audit, and a second direct assessment after repair is its one permitted re-audit. A failed first comprehension followed by a clean second assessment can clear comprehension; it does not need two clean rounds. If the second assessment still has a blocking gap, stop: there is no ordinary third assessment and no inner five-round budget to borrow. This feature's five actual comprehension allowances are consumed. The attributed stage review record owns the individual authorizations, inputs, findings and final clean reading; later critique repairs are not another comprehension assessment. Any further comprehension assessment requires a new explicit finite continuation. Implementation approval does not supply it.

At an exhausted outer allowance, inner five-round cap or churn stop, retain the actual findings/counts and send a specific host-governed continuation question to the captain. A continuation must name the stopped stage/invocation, which limit it extends, the pinned revised input and a finite additional review scope. Extending an inner cap does not extend the outer cap, and extending comprehension does not authorize critique/readiness or change their counters. Returning to drafting grants no additional review allowance by itself. Generated automatic-advance wording never clears unresolved blocking findings under project authority. Do not silently extend limits, treat a proposed repair as independent clearance or infer permission from implementation approval. A permissible risk decision is explicit and cannot fabricate a clean review, bypass an unresolved project blocker or grant merge/deployment authority.

The author classifies each finding with the resolver, records precise edits/disposition, applies authorized repairs and repins inputs before renewed review. When an ordinary allowed repeat requires the installed checkpoint, or an exception needs captain continuation, obtain that actual authorization before launch.

For each later edit the author records an impact decision: changed requirement/design decision, affected files and scenarios, affected prior review finding or evidence fact, and proposed repeat. The independent reviewer verifies that coverage decision; the first mate reconciles disputed scope. Pure wording repair needs review of affected explanations within the applicable unused allowance or specifically authorized continuation, not unrelated phase repetition. This does not authorize another comprehension assessment when its allowances are exhausted. Changed routing criteria, authority or review contracts reopen the affected design judgments.
