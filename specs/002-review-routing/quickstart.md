## Required observation record

For each route keep actual case/owner, intent source, read input paths and versions/hashes, classification reasons, stage/task identities and counts, reviewer status and context boundaries, reports/findings/dispositions, author commands/results/evidence, independent proof verdict and all gaps. Keep private host task details in task evidence/reports rather than public project history. A proposed assignment is not a launched review; an assigned reviewer is not a completed phase.

## Adverse outcomes and boundaries

Missing/stale spec, mismatched final trilogy, unavailable reviewer, unresolved blocking finding, contradictory standing direction or missing proof stops the affected step. Report the exact gap and owner; never fabricate a pass or bypass loop limits. Subsequent edits invalidate affected checks/reviews; new design decisions reopen affected scrutiny. Do not build sample changes without their own authority. The first mate owns unavailable session launches, direction activation and real both-route proof after merge. Repository alignment, activation and verification are distinct checkpoints, not a completed end-to-end claim. No time/cost saving is measured by this procedure.
