# Golden copy set — the pinned voice

`tests/golden/day-readings.json` pins the day-view copy: one entry per
day unit (the 18 transit-shape meaning units plus the honest quiet
unit). Each entry snapshots the strings the app renders for that unit's
**fixed input** — a synthetic transit hit defined in
`tests/content-golden.test.ts` (never the device clock, no ephemeris,
no network) — so a generator change that alters the voice fails `npm
test` until the changed copy has been re-read and re-pinned.

## What the goldens are

- **Real shipped copy, not placeholders.** Every snapshot is taken from
  the app's live rendering path (`selectDayReading` over the unit's
  fixed input), so the pinned tokens are exactly what the app displays.
- **Two blocks, two owners.** The `entries` block holds the text
  snapshots; the `approvals` block holds each unit's review status, and
  is the only place a status lives — it is never regenerated by the
  update run, only preserved verbatim. The pinning comment at the top
  of the JSON documents both blocks.
- **Provisional until the captain says otherwise.** Every unit's
  approval record starts `status: "provisional"` — this unit's text has
  not yet been through a captain-owned edit, so provisional copy is
  never passed off as approved. Flipping a unit to `"approved"` is the
  captain's own hand edit to the `approvals` block, made after
  reviewing the exact strings, always with the approving date in
  `approvedOn` (ISO, `YYYY-MM-DD`) and the review noted here. The suite
  fails any `approved` record without its date.

## Re-pinning after a reviewed copy change

```sh
GOLDEN_UPDATE=1 npm test -- --run tests/content-golden.test.ts
```

This rewrites the `entries` block from the live app copy (deterministic,
offline) and re-runs the checks. It carries the `approvals` block over
from the pinned file untouched — a re-pin can neither approve nor
de-approve anything, so a hand-made approval survives every re-pin. The
update run does not itself approve anything: status stays `provisional`
until the captain edits the `approvals` block by hand, with their review
as the basis.

## What else guards the voice

`tests/content-gate.test.ts` runs the mechanical voice rules over the
same corpus: banned promise/certainty/money/health vocabulary, story
shape (four paragraphs, imperative close, per-paragraph word and
syllable bounds), tier-2 astrological containment, and the approved
aspect terms in the unit's non-story fields. The goldens pin the exact
wording; the gate pins the rules the wording must obey.
